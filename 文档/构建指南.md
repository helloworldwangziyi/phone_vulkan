# estarx_vulkan 构建指南

## 环境要求

### Android 构建

- JDK 17（推荐 Eclipse Temurin）
- Android SDK API 34
- Android NDK（项目未指定 `ndkVersion`，默认使用 `ndk.dir` 或 SDK 中的默认 NDK）
- 支持 Vulkan 的 Android 设备或模拟器（API 24+）

### 桌面构建（仅验证核心）

- CMake 3.22.1+
- C++17 编译器（MSVC / GCC / Clang）
- Vulkan SDK

## Android 构建步骤

```bash
cd estarx_vulkan

# 构建 Debug APK
./gradlew :samples:android:app:assembleDebug

# 产物位置
# samples/android/app/build/outputs/apk/debug/app-debug.apk
```

安装并运行：

```bash
# 连接真机或启动模拟器
adb devices

# 安装
./gradlew :samples:android:app:installDebug

# 启动
adb shell am start -n com.estarx.vulkansample/.MainActivity
```

## 桌面 CMake 构建步骤

Windows + Visual Studio 2022：

```bash
cd estarx_vulkan
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Debug
```

Linux/macOS：

```bash
cd estarx_vulkan
mkdir build && cd build
cmake ..
cmake --build .
```

这会编译出 `estarx_vulkan_core` 静态库，用于验证 `core/` 目录下的 C++ 代码可以脱离 Android 编译。注意桌面版本目前没有可执行示例（没有 `main()`），需要你自己实现一个 `IPlatform` 和窗口循环。

## 常见问题

### 1. 构建时提示 `VK_KHR_ANDROID_SURFACE_EXTENSION_NAME` 未定义

确保 Android 构建时定义了 `VK_USE_PLATFORM_ANDROID_KHR`。本项目已在 `samples/android/app/src/main/cpp/CMakeLists.txt` 中处理：

```cmake
if (ANDROID)
    target_compile_definitions(estarx_vulkan PRIVATE VK_USE_PLATFORM_ANDROID_KHR)
endif()
```

### 2. Kotlin 依赖冲突

错误示例：

```text
Duplicate class kotlin.collections.jdk8.CollectionsJDK8Kt found in modules ...
```

已在 `samples/android/app/build.gradle` 中通过 `resolutionStrategy` 强制 Kotlin stdlib 版本为 1.8.22 并排除旧版 `kotlin-stdlib-jdk7/jdk8`。

### 3. 模拟器上黑屏或闪退

- 确认模拟器 AVD 支持 Vulkan。Android Emulator API 30+ 通常支持。
- 在 `adb logcat` 中搜索 `estarx-vulkan` 查看日志。
- 真机通常更稳定，优先用支持 Vulkan 的真机测试。

### 4. 如何看日志

```bash
adb logcat -s estarx-vulkan:D estarx-validation:D *:S
```

## 从 Android Studio 打开

直接打开桌面上的 `estarx_vulkan` 文件夹即可。Gradle 同步可能需要几分钟下载依赖。
