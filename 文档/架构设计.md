# 架构设计

> 随框架重建同步更新，仅描述当前已落地的结构；规划中的部分明确标注。

## 分层

```
┌─────────────────────────────────────┐
│ App（samples/app，所有平台共用）       │
│   页面创建、布局、状态与业务动作回调      │
├─────────────────────────────────────┤
│ 平台薄壳 platform/                   │
│   surface / pointer / VSync / 生命周期  │
├─────────────────────────────────────┤
│ 公共核心 core/（平台无关 C++17）        │
│   ui/view    视图树（布局/绘制回调/命中） │
│   ui/input   Pointer 标准化后的输入分发  │
│   ui/animator VSync 逐帧动画驱动        │
│   ui/controls Button/ScrollView/Navigation│
│   ui/canvas  帧画布（顶点流 + clip 栈）  │
│   esx_view   句柄 ABI + 帧构建          │
│   render_loop requestRender / setFrameFunc│
│   renderer  Vulkan 渲染器（渲染 Canvas）│
│   event     事件分发接口（event.h）     │
│   log       spdlog 封装（log.h）      │
│   platform  IPlatform 抽象（platform.h）│
├─────────────────────────────────────┤
│ third_party/spdlog、glm（header-only）│
└─────────────────────────────────────┘
```

设计要点：所有平台相关代码收敛在薄壳层；`core/` 不含任何平台 API；
除各平台启动入口外，App 页面与业务代码只保留一套。

## 输入链路（安卓 → SDK UI）

```
VulkanSurfaceView.onTouchEvent                   Android 薄壳
  → NativeBridge.nativeOnTouch（含事件时间戳）
  → PointerAction + PointerEvent                 平台动作标准化
  → ui::dispatchPointerEvent                     SDK 输入入口
  → View 树 hit test / 手势目标选择 / 滑动速度估计（约 100ms 窗口）
  ├─ Button 内部 pressed/cancel/up → onClick     语义化控件回调
  ├─ ScrollView 拖动/惯性/回弹 → onScroll        语义化控件回调
  └─ Navigation 左缘滑动返回                      语义化控件回调
```

全局事件只保留 surface 生命周期：`AppStart` / `SurfaceChanged` / `SurfaceDestroyed`。
init 时 bridge 在 `AppStart` 之前先报一次 `SurfaceChanged`（携带真实 surface 像素尺寸），
App 建视图树时即可按真实像素布局；之后的尺寸变化仍由 `nativeResize` 通道上报。
行情、交易和网络数据模型暂未引入，后续不得与 View 输入重新混入同一个全局总线。

## 视图与绘制模型

- 单一 `View` 类组织成树：`rect` 相对父视图，遍历重算 `actualX/Y`（屏幕坐标）；
- App 不直接持有 `View*`，经 `esx_view` 句柄（uint32_t）操作，见 `esx_view.h`；
- 绘制单位是"帧"：`esxBuildFrame` 重算 actual，然后按
  `View 背景 → View draw callback → children` 的顺序遍历；
  draw callback 中的 `esx_draw_*` 写入当前帧 `Canvas`（顶点流 + clip 栈），
  最后 `renderer.render(canvas)` 一次性提交；
- 坐标为像素坐标，renderer 用 push constant 传 `glm::ortho(0, w, 0, h)` 投影；
- clip = 视图矩形与父链矩形的交集，落到 Vulkan scissor。

## 重绘模型

当前是 **VSync + dirty 合并模型**：`requestRender()` 只标记 dirty；Android
`Choreographer` 在系统 VSync 调 `beginFrame(frameTimeNanos)`，只有 dirty 时
才构建并提交一帧。同一个 VSync 前的多次状态更新只产生一次绘制。

动画由同一个 VSync 驱动：`beginFrame` 先 tick `ui/animator` 注册的逐帧动画
（消费 `frameTimeNanos`），动画内修改视图会再次置 dirty，形成自持续的逐帧
推进，直到动画结束。导航转场、滚动惯性和回弹都建立在这套 animator 上；
动画 tick 内用句柄重解析 + `weak_ptr` 持有控件状态，视图销毁后动画自动退场。

## 导航与转场

- `Navigation` 控件维护页面栈：页面须 `esx_create_view(parent=0)` 创建，
  push 时经 core 内部 `esxAdoptChild` 挂进页面容器，布局由 Navigation 接管
  （页面区域 = 导航栏以下全部空间）；
- push/pop 转场统一用"顶层页面滑出进度 p"表示：p=0 盖严，p=1 完全滑出；
  下层页面按 0.28 比例视差后退/归位，动画 280ms easeOutCubic；
- 左缘 48px 热区内的右滑手势由 Navigation 的 pan callback 认领，松手时按
  速度（>400px/s）或进度（>0.5）决定完成返回还是回弹取消；
- 导航栏高度由创建参数指定，栈深 >1 时显示返回按钮（引擎暂无文字渲染，
  只画箭头，无标题）；
- pop 动画完成后销毁页面，App 可在 `on_pop` 回调里释放页面相关数据；
- 转场进行中忽略新的 push/pop；尺寸变化时取消转场并吸附到最终状态。

## 线程模型

当前为**单 UI 线程模型**：VSync、输入分发、View 修改和渲染都在 Android UI
线程执行。App 回调可改状态并请求下一帧，不会在回调栈里递归渲染。

后台数据源的线程切换和所有权模型后续单独设计，不复用栈上 `void*` 生命周期事件。

## 日志

`evk::log::init(tag)` 在薄壳启动时调用一次：Android 输出到 logcat
（tag 同名），桌面输出 stdout；鸿蒙预留 hilog 扩展位。
全局使用 `EVK_LOGD/I/W/E` 宏，fmt 风格 `{}` 格式串。

## 跨端现状与规划

| 平台 | 薄壳形态 | 事件源 |
|---|---|---|
| Android | Java SurfaceView + JNI（已实现） | MotionEvent / Choreographer / SurfaceHolder |
| iOS | Metal/Vulkan View 薄壳（规划） | Touch / DisplayLink / surface 生命周期 |
| 鸿蒙 | NDK XComponent + C++ 壳（规划） | Touch / VSync / surface 生命周期 |

各端共用 `core/` 和 `samples/app/`；平台薄壳只翻译输入动作、提供 VSync 与
surface。渲染器由 `IPlatform` 注入各端 surface 实现。
