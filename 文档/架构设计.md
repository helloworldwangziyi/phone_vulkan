# 架构设计

## 分层

~~~
App
  StatefulWidget / State / build / Navigator::of(context)
                |
Element tree
  mount / update / rebuild / unmount / BuildContext
                |
View tree
  Flex / Button / ScrollView / Navigation / paint / hit test
                |
Canvas（纯 CPU 顶点流 + Batch，帧契约）
                |
Compositor
  buildFrame -> 首帧日志 -> Renderer::render
                |
GPU 后端（core/src/gpu/）
  VulkanContext / Swapchain / UiPipeline / TextureCache
                |
Android / iOS platform shell
  surface / pointer / VSync / lifecycle
~~~

整个 UI SDK 是 C++17 对象接口。C 链接只存在于 JNI、Objective-C 和平台工厂
这类操作系统边界，不进入 App 或 UI 模块。

## Widget、Element、View

- Widget 是不可变配置，可频繁创建和销毁。
- Element 是挂载身份，按同位置同类型更新，持有 State 和 BuildContext。
- View 是内部 retained render object，持有实际尺寸、父子关系和交互状态。
- Element 卸载时按树顺序移除 View，C++ 所有权直接完成资源回收。
- ViewRef 由裸地址和生命周期令牌组成，输入与动画可检测目标是否已经销毁。

这与 Flutter 的 Widget / Element / RenderObject 分工一致。App 不直接操作
View，因此不需要理解对象树的所有权规则。

## 布局

App 通过 Column、Row、Expanded、SizedBox、Padding、Center 组合布局。
FlexParentData 仅存在于渲染层，由这些 Widget 自动生成。

SurfaceChanged 只调用 setViewportSize。Navigator 根 View 更新尺寸后，
Navigation、Flex、Padding、SizedBox 与 ScrollView 自顶向下同步布局。

## 输入

~~~
平台 PointerEvent
  -> View hit test
  -> 最近的 pointer / pan 接收者
  -> 触控阈值判定
  -> Button、ScrollView 或 Navigation
~~~

一次手势选定 pan 接收者后会锁定到 End 或 Cancel，不会因接收者中途进入动画
状态而重新竞争。这与 Flutter 手势竞技场 winner 的生命周期一致。

## 绘制

buildFrame 更新 actual 坐标，然后按背景、自定义 PaintContext、children 的顺序
遍历 View 树。PaintContext 把局部坐标转换为屏幕坐标，并自动应用父链 clip。
Canvas 生成顶点流和 scissor batch，Compositor 把它交给 Renderer 一次提交当前帧。

Renderer 瘦身为帧编排（acquire → 录制 → 提交 → present），GPU 设施拆成
core/src/gpu/ 四个模块：VulkanContext（instance / surface / 设备 / 队列）、
Swapchain（交换链 / MSAA / render pass / framebuffer）、UiPipeline（唯一
UI 管线）、TextureCache（白纹理 / 采样纹理 / descriptor / 上传中转）。
TextureCache 经 gpu::ITextureSource 接口读取纹理（数量 / 尺寸 / mip 链 /
脏页），UI 层用 header-only 适配器 texture_store_source.h 把 TextureStore
接入，渲染器不再直接依赖 UI 层单例。

Canvas 图元在 CPU 侧三角化：矩形/线段/渐变直接出三角形；圆/椭圆/圆弧用
扇形与内外弧条带逼近（分段数可调）；圆角矩形分解为十字矩形 + 四角四分圆；
描边用边矩形 + 角环拼装。全部图元共享"纹理 × 顶点色"着色公式——纯色与
渐变走白纹理（渐变靠顶点插值），图像与文字走 TextureStore 纹理。

## 文字与纹理

- `FontEngine`（core/src/ui/font_engine.cpp）：stb_truetype 解析 TTF，
  按（字体, 字形, 整数字号）缓存光栅化结果，货架法打进 1024×1024 的
  R8 atlas；多字体按注册顺序回退（Latin 在前、CJK 补全），一行混排
  自动分派。纯 CPU 模块，无 Vulkan 依赖，主机测试可直接跑。
- `TextLayout`（core/src/ui/text_layout.cpp）：定宽多行排版。经
  FontEngine::measureGlyphs 逐码点量宽（不光栅化），按从简规则断行：
  `\n` 强断、CJK 前后任意断、英文按词断（超宽回退到行内最近空格，
  断点空格丢弃）、超长词硬断。结果以（文本, 字号, 字体, 宽度）为键
  缓存；绘制逐行调 Canvas::drawText，只画与 clip 相交的行。
  Text 控件传 softWrap=true 即按视图宽度换行：宽度由父布局写入，
  高度 = 行数 × 行高，由视图经 setFlexChild 回灌给 Flex 父容器。
- 管线统一为"纹理 × 顶点色"：片元恒输出 `(color.rgb, color.a × texture.r)`，
  纯色/渐变批次绑 1×1 白纹理（采样恒为 1），文字批次绑 atlas 页；
  同一条管线，按 Canvas 批次的 textureId 换绑 descriptor set。
- 字形按需光栅化：首帧绘制文字时进 atlas 并打脏页标记，TextureCache 在
  帧首把脏页整页上传（中转缓冲按 in-flight 帧分槽，避免写读竞争）。
- 字体二进制与 shader 同法内嵌：cmake/embed_font_assets.cmake 生成
  字节数组头，资产在 core/assets/fonts/（Roboto + Noto Sans SC，OFL 许可）。
  示例 App 用 text() 组合中英文混排（samples/app/app_fonts.cpp）。
- TextureStore 是全部非白纹理的登记处：字形 atlas 页与业务位图
  （drawImage / ImageWidget）共用同一套 id、RGBA 像素与脏页语义；
  渲染器按 id 建 descriptor，脏纹理帧首整张上传（中转缓冲按 in-flight
  帧分槽，容量 2 个 RGBA 页，溢出顺延下一帧）。容器层 Container 支持
  圆角与描边（cornerRadius/borderColor/borderWidth）。

## 状态与重建

State::setState 立即重跑当前 State 的 build。Element 比较新旧 Widget：

- 同位置同类型：更新配置，保留原 View 和内部状态；
- 类型不同：unmount 旧 Element，再 mount 新 Element；
- 子项增删：只处理对应位置。

滚动 offset、按钮 pressed、导航动画都位于 View 层，不会因 Widget 重建丢失。

## 导航

Navigator 持有 Route 列表，每条 Route 持有页面 Element 树。push 与 pop 负责：

1. 派发 WillLeave / WillEnter；
2. 执行滑动转场（返回入口：导航栏返回键，或平台壳上报的 BackPressed 事件——
   Android 返回键/手势、iOS 壳层边缘手势）；
3. 派发 DidLeave / DidEnter；
4. pop 完成后 unmount 并销毁 Route。

App 通过 Navigator::of(context) 使用导航，不接触页面 View。

## 事件与线程

UI 为单线程模型。EventBus 使用 std::function 和可移动的 RAII Subscription。
State 销毁时订阅自动取消；页面隐藏时 scoped subscription 暂停派发。

postUi 是后台线程进入 UI 线程的入口。任务在下一次 beginFrame 开头执行，
任务中的 setState 可在同一帧进入构建和绘制。

## 帧调度

requestRender 只设置 dirty。平台 VSync 调 beginFrame：

1. drainUiTasks；
2. tickAnimations；
3. dirty 时调用平台注册的 FrameFunc；
4. buildFrame 生成 Canvas；
5. Renderer 提交 Vulkan 命令。

多个状态更新会合并到一次 VSync。
