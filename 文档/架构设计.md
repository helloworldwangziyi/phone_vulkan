# estarx_vulkan 架构设计

## 设计目标

Vulkan 是显式、底层的图形 API，不同操作系统创建 Surface、查询窗口尺寸、输出日志的方式差异很大。为了**让同一份渲染逻辑跨平台复用**，本项目采用三层架构：

```text
┌─────────────────────────────────────┐
│           samples/android           │  示例应用层：Activity、布局、生命周期
│    (MainActivity / VulkanSurfaceView) │
├─────────────────────────────────────┤
│         platform/android            │  平台适配层：JNI 桥接、ANativeWindow
│    (bridge.cpp / platform_android)   │
├─────────────────────────────────────┤
│              core                   │  平台无关核心：Vulkan 渲染器
│    (evk::Renderer / evk::IPlatform)  │
└─────────────────────────────────────┘
```

## 核心抽象：IPlatform

`core/include/evk/platform.h` 定义了平台必须提供的接口：

```cpp
class IPlatform {
public:
    virtual ~IPlatform() = default;

    // 根据平台原生窗口创建 VkSurfaceKHR
    virtual bool createVulkanSurface(VkInstance instance, VkSurfaceKHR* surface) = 0;

    // 返回绘图区域像素尺寸
    virtual void getSurfaceSize(uint32_t* width, uint32_t* height) = 0;

    // 日志输出（Android 用 __android_log_print，桌面可用 printf/stderr）
    virtual void log(LogLevel level, const char* tag, const char* fmt, va_list args) = 0;
};
```

`evk::Renderer` 只调用这三个接口，因此：

- 移植到桌面时，只需实现 GLFW/Win32 版本的 `IPlatform`。
- 移植到 HarmonyOS 时，只需实现 `OH_NativeXComponent` 版本的 `IPlatform`。
- 核心 `renderer.cpp` 一行都不用改。

## Renderer 生命周期

```cpp
evk::IPlatform* platform = createAndroidPlatform(env, surface);
evk::Renderer* renderer = new evk::Renderer(platform);
renderer->initialize();   // 创建 Vulkan 全套对象
renderer->render();       // 绘制一帧
renderer->setSize(w, h);  // 通知尺寸变化，下一次 render 会重建 Swapchain
renderer->shutdown();     // 销毁所有 Vulkan 对象
delete renderer;
destroyAndroidPlatform(platform);
```

### initialize() 内部顺序

1. `createInstance()`：创建 Vulkan Instance，启用 `VK_KHR_surface` 与平台相关的 Surface 扩展。
2. `createSurface()`：通过 `IPlatform::createVulkanSurface()` 创建 VkSurfaceKHR。
3. `pickPhysicalDevice()`：选择同时支持 Graphics Queue 和 Present Queue 的物理设备。
4. `createLogicalDevice()`：创建逻辑设备，获取 `graphicsQueue` 与 `presentQueue`。
5. `createSwapchain()`：创建交换链，使用 Surface Capabilities 的 `currentTransform` 做 pre-transform。
6. `createImageViews()` / `createRenderPass()` / `createGraphicsPipeline()` / `createFramebuffers()`：标准管线对象。
7. `createCommandPool()` / `createCommandBuffers()` / `createSyncObjects()`：命令与同步对象。
8. `createVertexBuffer()`：上传三角形顶点数据。

## Android 平台层数据流

```text
Activity.onCreate()
    └── setContentView(R.layout.activity_main)
            └── VulkanSurfaceView 加入视图树
                    └── surfaceCreated()
                            └── NativeBridge.nativeInit(Surface)
                                    └── bridge.cpp: Java_com_estarx_vulkan_NativeBridge_nativeInit()
                                            └── evkCreateAndroidPlatform(env, surface)
                                                    └── ANativeWindow_fromSurface()
                                            └── renderer->initialize()
                                                    └── vkCreateAndroidSurfaceKHR()
```

尺寸变化时：

```text
VulkanSurfaceView.surfaceChanged(width, height)
    └── NativeBridge.nativeResize(width, height)
            └── renderer->setSize(width, height)
```

绘制时：

```text
VulkanSurfaceView.surfaceChanged() 末尾
    └── NativeBridge.nativeRender()
            └── renderer->render()
```

## 跨平台扩展思路

若未来需要支持桌面 GLFW，只需新增一个文件，例如 `core/src/platform_glfw.cpp`：

```cpp
class GlfwPlatform : public evk::IPlatform {
public:
    bool createVulkanSurface(VkInstance instance, VkSurfaceKHR* surface) override {
        return glfwCreateWindowSurface(instance, window_, nullptr, surface) == VK_SUCCESS;
    }
    void getSurfaceSize(uint32_t* width, uint32_t* height) override {
        int w, h;
        glfwGetFramebufferSize(window_, &w, &h);
        *width = w; *height = h;
    }
    void log(LogLevel level, const char* tag, const char* fmt, va_list args) override {
        vfprintf(stderr, fmt, args);
    }
};
```

然后桌面示例里用这个 `GlfwPlatform` 构造 `evk::Renderer` 即可。
