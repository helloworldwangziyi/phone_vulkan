# 架构设计

> 随框架重建同步更新，仅描述当前已落地的结构；规划中的部分明确标注。

## 分层

```
┌─────────────────────────────────────┐
│ App（samples 演示，未来业务层）        │
│   app_main.cpp：注册 EventFunc，建视图、 │
│   响应 Draw / UiClick（双端共用同一份）│
├─────────────────────────────────────┤
│ 平台薄壳 platform/                   │
│   android: Java SurfaceView + JNI bridge │
│   ios: Obj-C++ EVKRenderView + bridge.mm │
│        + EVKMetalRenderer（Metal 渲染） │
├─────────────────────────────────────┤
│ 公共核心 core/（平台无关 C++17）        │
│   ui/view    视图树（rect/children/命中）│
│   ui/canvas  帧画布（顶点流 + clip 栈）  │
│   esx_view   句柄 ABI + 帧构建 + 触摸分发│
│   render_loop requestRender / setFrameFunc│
│   renderer  Vulkan 渲染器（渲染 Canvas）│
│   event     事件分发接口（event.h）     │
│   log       spdlog 封装（log.h）      │
│   platform  IPlatform 抽象（platform.h）│
├─────────────────────────────────────┤
│ third_party/spdlog、glm（header-only）│
└─────────────────────────────────────┘
```

设计要点：所有平台相关代码收敛在薄壳层；`core/` 不含任何平台 API，
Android / iOS 已复用同一份 core。iOS 的 Metal 渲染器也在薄壳层
（与 core 的 Vulkan renderer 平级，渲染同一份 `ui::Canvas`）。

## 事件链路（安卓 → App）

```
VulkanSurfaceView.onTouchEvent(action, x, y)     Java 薄壳
  → NativeBridge.nativeOnTouch                   JNI 声明
  → bridge.cpp: esxDispatchTouch(action, x, y)   core 触摸分发
  → 命中测试 + 12px slop 判点击                  esx_view.cpp
  → evk::dispatchEvent(EventId::UiClick, &data)  公共出口
  → 已注册的 EventFunc(id, data)                  App 侧处理
```

surface 生命周期同链路转发：`AppStart` / `SurfaceChanged` / `SurfaceDestroyed`。
帧构建时逐可见视图发 `Draw` 事件，App 在回调内调 `esx_draw_*` 画到自己视图上。

iOS 链路同构：

```
EVKRenderView.touchesBegan/...           Obj-C++ 薄壳（点坐标 × contentsScale → 像素）
  → bridge.mm: evkIOSTouch(action, x, y) 转发层
  → esxDispatchTouch → dispatchEvent     与 Android 同一 core 链路
```

生命周期对应：`didMoveToWindow` ≈ surfaceCreated/Destroyed，
`layoutSubviews` ≈ surfaceChanged（先同步 drawableSize 再画一帧）。
唯一差异在渲染出口：Android 走 core 的 `evk::Renderer`（Vulkan），
iOS 走薄壳自带的 `EVKMetalRenderer`（Metal），两者吃同一份 `Canvas`。

约定（对齐 estarx 模型）：

- 事件经 `EventFunc(EventId, const void* data)` 同步回调；
- `data` 为各事件对应的栈上结构体，**仅在回调期间有效**，需要跨调用保存时必须拷贝；
- 传哪些事件、data 带什么字段，集中定义在 `core/include/evk/event.h`。

## 视图与绘制模型

- 单一 `View` 类组织成树：`rect` 相对父视图，遍历重算 `actualX/Y`（屏幕坐标）；
- App 不直接持有 `View*`，经 `esx_view` 句柄（uint32_t）操作，见 `esx_view.h`；
- 绘制单位是"帧"：`esxBuildFrame` 重算 actual → 画背景 → 逐视图发 `Draw`，
  App 的 `esx_draw_*` 调用写入当前帧 `Canvas`（顶点流 + clip 栈），
  最后 `renderer.render(canvas)` 一次性提交；
- 坐标为像素坐标，renderer 用 push constant 传 `glm::ortho(0, w, 0, h)` 投影；
- clip = 视图矩形与父链矩形的交集，落到 Vulkan scissor。

## 重绘模型

当前是**按需直调**：App 调 `requestRender()` → 立即同步画一帧
（`render_loop.h`，平台壳经 `setFrameFunc` 注册实现）。
规划：换 VSync + dirty 合并模型（对齐 Choreographer），只改
`render_loop.cpp` 实现，`requestRender()` 接口不变。

## 线程模型

当前为**单 UI 线程同步模型**：渲染（`nativeRender`）与事件分发都在 Android UI
线程上直接调用，无队列、无锁。JNI 调用不做线程切换。

规划：若后续引入独立渲染线程或后台事件源（网络等），在 `dispatchEvent`
内部加跨线程队列并在渲染循环泵送，`EventFunc` 接口保持不变。

## 日志

`evk::log::init(tag)` 在薄壳启动时调用一次：Android 输出到 logcat
（tag 同名），桌面输出 stdout；iOS 当前同桌面走 stdout（Xcode 控制台可见），
鸿蒙预留 hilog 扩展位。
全局使用 `EVK_LOGD/I/W/E` 宏，fmt 风格 `{}` 格式串。

## 跨端现状与规划

| 平台 | 薄壳形态 | 事件源 |
|---|---|---|
| Android | Java SurfaceView + JNI（已实现） | onTouchEvent / SurfaceHolder.Callback |
| iOS | Obj-C++ EVKRenderView + Metal 渲染器（已实现） | touchesBegan 等 / view 生命周期 |
| 鸿蒙 | NDK XComponent + C++ 壳（规划） | 触摸回调 / surface 回调 |

各端共用：`core/` 的 ui、esx_view、render_loop、event、log
接口与 data 结构体定义。渲染器按端实现：Android 用 core 的 Vulkan
`renderer`（`IPlatform` 注入 surface），iOS 用薄壳层
`platform/ios/EVKMetalRenderer`（Metal，无 `IPlatform` 依赖）。
