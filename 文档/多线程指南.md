# 多线程指南

三端共享同一套线程模型，网络能力暂缓。

| 线程 | 独占对象与工作 |
|---|---|
| Platform / UI（当前共用） | 平台事件、Widget/Element/State/View、字体排版与字形生成、TextureStore 单例、Canvas 构建、语义树与平台通道 |
| Raster（每个 Compositor 一条） | Renderer、全部 Vulkan 对象、纹理副本、RGBA/mip 转换、顶点和纹理上传、录制/提交/呈现 |
| Worker（共享池默认 1~4 条） | 值消息上的纯计算；不能访问 UI 树、字体单例、纹理单例或 Vulkan |

## 帧交接与生命周期

`Compositor::renderFrame` 在 UI 构建 Canvas，然后把纹理脏矩形复制进帧。
`FramePipeline` 两个槽循环复用，包含当前正在执行的帧：Raster 提交 N 时，
UI 可以构建 N+1。槽位占满就保留绘制请求，下一次 VSync 再取最新 UI 状态；
不等待 GPU，不积压无界历史帧，也不提前清除纹理脏标记。

Raster 使用自己的纹理原图副本。UI 可以继续写 atlas，Raster 不会读到一半
更新的像素；原图副本也支持上传失败后的重试。代价是一份额外的 CPU 纹理
内存及在途帧的脏区快照。字形生成仍在 UI，异步图片解码是独立待办。

平台只调 `Compositor::setSize/requestSwapchainRebuild`，不能持有 Renderer。
resize 后尚未执行的旧几何会被跳过，但其纹理增量仍按序应用，防止丢字形。
等待 GPU fence/交换链图像使用有限超时，超时或尺寸尚不稳定会请求后续帧。
初始化失败和致命渲染失败在 Raster 清理资源，后者等待平台重建引擎恢复。

Surface 销毁时先停止 VSync、清除 FrameFunc，再销毁 Compositor。析构停止
接帧、舍弃排队几何、等待正在执行的 Raster 及 GPU 清理完成，之后才释放
IPlatform/原生窗口。新 Compositor 首帧完整发送纹理，即使 UI 脏标记已清除。
Android 的 ANativeWindow 在 UI 通过 JNI 获取，Raster 不持有 JNIEnv；
iOS 的 drawableSize 在 UI 获取，resize 后使用尺寸快照。

## Worker 消息

```cpp
#include "evk/worker_pool.h"

// 作为 State 成员保存，dispose() 中 cancel()；不能作为临时值丢弃。
evk::WorkerTask task_;

void startCalculation(std::vector<float> input) {
    task_ = evk::WorkerPool::instance().compute(
        std::move(input),
        +[](std::vector<float> values) { // + 将无捕获 lambda 转成函数指针
            for (auto& value : values) value *= 2;
            return values;
        },
        [this](std::vector<float> result) { // 只在 UI 执行
            setState([&] { values_ = std::move(result); });
        },
        [this](std::exception_ptr error) { /* UI 上处理失败 */ });
    if (!task_) { /* 等待队列已满，可稍后重试 */ }
}

void dispose() override { task_.cancel(); }
```

输入与结果支持移动所有权（如 vector、unique_ptr）；work 必须是普通函数或
无捕获 lambda。API 拒绝顶层裸指针/引用，C++ 不能检查消息内部是否含 UI
指针或共享可变成员，因此嵌套对象的所有权仍由调用者负责。work 不得经全局
变量绕过这条约定；不要让 work 反过来等待 UI，也不要在线程池里睡眠计时。

`WorkerTask` 析构、替换、cancel 都会抑制尚未执行的计算及未交付的回调。
已经运行的计算自然结束，不强行中断。取消句柄和 State 生命周期在 UI 串行
操作：dispose 后，即使结果已排入 UI 队列，也不会再调用捕获 this 的回调。
不提供 onError 时异常结果被丢弃，建议业务显式处理。多线程完成顺序不保证
与提交顺序一致；同一业务目标发新请求时替换旧句柄即可抑制旧结果。

默认最多 64 个等待任务，队列满时返回空句柄；可构造独立 WorkerPool 调整
线程数与队列上限。线程池须由拥有者在线程池外析构，关闭时取消未交付结果
并 join 在运行的任务。`postUi` 自动 requestRender，在下次 VSync 帧头执行。

自选页为完整示例：VSync 计时触发本地快照计算，Worker 随机游走及格式化，
UI 接收结果后 setState；删除行会取消旧快照，退出页面取消任务和计时器。

## 观测与验证

`FrameMetrics::instance().snapshot()` 可从任意线程读取最近成功帧，以及累计
成功帧数/队列满导致的延后次数。`FrameTiming` 记录 UI 任务、动画、同步
重建、布局、绘制、纹理快照、排队、Raster、顶点上传的 CPU 毫秒耗时。
日志 `[evk][render][frame_timing ...]` 首帧及每 120 个成功帧输出一次。

阶段存在包含关系（UI 任务可能同步重建，Raster 包含上传），不能把所有字段
相加；只统计 beginFrame 内的 UI 工作，不含此前输入事件中的同步 setState。
Raster 包含等待 fence/acquire/present，不能当成 GPU 执行时间。FPS/屏幕
overlay 和设备上的改造前后对比仍待补充。

退前后台及 Surface 重建，未观察到应用崩溃或渲染失败。日志确认 UI 与
