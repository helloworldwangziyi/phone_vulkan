# 示例应用导读

> 本文说明 `samples/` 示例应用怎么做：展示什么、启动链路、页面写法、
> 以及支撑这套写法的声明式 UI 层。当前 sample 正处于「手写 C ABI →
> 声明式（仿 Flutter）Component」的重构中间态，本文描述的是重构后的现状。
>
> 与「架构设计」「源码导读」的关系：前者讲分层与机制，后者按文件讲地图；
> 本文按「一条链路 + 一个页面」讲清楚 App 侧怎么用这套框架。

## 1. 示例展示什么

APK 打开后是一个可 push 详情页、可无限嵌套、可切主题、带模拟行情列表的 App：

- **首页 `HomePage`**（`samples/app/main_page.*`）：顶部渐变面板（点击切换
  强调色）、「进详情页」主按钮、「切主题」次按钮、一个可滚动的模拟行情列表。
- **详情页 `DetailPage`**（`samples/app/detail_page.*`）：渐变主视觉 +
  2×2 色卡 + 「继续 push」按钮，可无限嵌套（每层 `variant` 递增，配色轮换）。

这两个页面覆盖了框架全部演示点：Flex 布局、Button/ScrollView/Navigation
控件、事件总线换肤、后台线程异步数据回 UI 线程、导航转场。

## 2. 启动链路（Android 薄壳 → 公共 App）

整条链路是 `布局 XML → Java 薄壳 → JNI → core → 公共 App`：

```
activity_main.xml
  └─ com.estarx.vulkan.VulkanSurfaceView        samples/android/.../res/layout/activity_main.xml
       ├─ surfaceCreated → nativeInit(Surface)   platform/android/java/.../VulkanSurfaceView.java
       ├─ Choreographer 每帧 → nativeBeginFrame
       └─ onTouchEvent → nativeOnTouch
NativeBridge.java  ← System.loadLibrary("estarx_vulkan")
  └─ bridge.cpp 翻译成 core 事件                 platform/android/cpp/bridge.cpp
       nativeInit → 建 Renderer + setFrameFunc + setEngineReady(true)
                     + 先报一次 SurfaceChanged + 首次报 EngineReady
       nativeBeginFrame → evk::beginFrame()      （只有 dirty 才真画）
       nativeOnTouch   → evk::ui::dispatchPointerEvent()
       nativeDestroy   → 停动画/输入 → 报 SurfaceDestroyed → 拆渲染器
公共 App 入口：
  samples/app/app_main.cpp 的 appEvent() 收到事件后建/拆视图树
```

各环节职责：

| 文件 | 职责 |
|---|---|
| `VulkanSurfaceView.java` | 向系统拿 surface、收触摸、跑 Choreographer VSync 循环，原样转发给 JNI，不含业务逻辑（"薄壳"的含义） |
| `NativeBridge.java` | JNI 方法声明 + `System.loadLibrary("estarx_vulkan")` |
| `bridge.cpp` | 解包参数 → 翻译成 core 事件；只转发，不写业务 |
| `app_main.cpp` | 公共 App 唯一入口：注册生命周期回调、建/拆视图树 |

`bridge.cpp` 里的两个关键约定：

- `nativeInit` 时 **EngineReady 之前先报一次 SurfaceChanged**（携带
  ANativeWindow 真实像素尺寸），App 建视图树时即可按真实像素布局；
  之后的尺寸变化由 `nativeResize` 通道上报。
- `nativeBeginFrame` 每帧都进来，但 core 的 `beginFrame` 只在 dirty 时
  真正构建并提交帧（见「架构设计」的重绘模型）。

## 3. 公共 App 入口（app_main.cpp）

- 用 `AppBootstrap` 全局对象的构造函数在 `main` 之前注册 `setEventFunc`，
  页面与业务代码无需任何显式初始化调用。
- 事件处理：

| 事件 | 动作 |
|---|---|
| `EngineReady` | `appCreateUi()`：创建 `Navigation` 根视图 + `pushPage(HomePage)` |
| `SurfaceChanged` | `appSetScreenSize()` 更新设计像素基准 + `esx_view_set_bounds` 调整根视图；页面内容重排由 Flex 级联完成 |
| `SurfaceDestroyed` | `appDestroyUi()`：先 `teardownAllComponents()` 清页面回调槽/事件监听，再 `esx_destroy_view` 销毁整棵视图树 |

## 4. 页面写法（声明式 Component）

页面不再手写 `create/layout/destroy`，而是继承 `evk::ui::Component`，
**把整棵 UI 描述成 `build()` 返回的 Widget 树**，成员变量即页面状态。
结构即代码：Widget 嵌套关系 = 视图树父子关系，创建了什么、挂在哪一眼可见。

### 4.1 首页 HomePage

```cpp
std::unique_ptr<Widget> HomePage::build() {
    // Box：背景 + onTap + onDraw ≈ Container+GestureDetector+CustomPaint
    auto panel = Box(theme.surface);
    panel.onTap = [this] { setState([this]{ panelAccent_ = !panelAccent_; }); };
    panel.onDraw = [this](esx_view v){ drawPanelGradient(v, panelAccent_); };
    panel.layout.main = appCalcHeight(540);          // 主轴固定高度
    panel.layout.marginMainBefore = appCalcHeight(60);

    auto detailButton = ButtonW(primaryStyle);
    detailButton.onTap = [this] {
        pushPage(nav(), std::make_unique<DetailPage>(detailCount_++), true);
    };
    detailButton.layout.cross = appCalcWidth(400);
    detailButton.layout.align = ESX_FLEX_ALIGN_CENTER;   // 交叉轴居中

    // 数据驱动的列表：占位行 ↔ 真实数据行（reconcile 自动增删）
    std::vector<std::unique_ptr<Widget>> rows;
    if (!quoteLoaded_) {
        rows.push_back(makeWidget(Box(surfaceRaised).mainSize(400)));
    } else {
        rows = mapWidgets(quotes_, [](uint32_t c){
            return Box(c).mainSize(122).marginMain(0, 30);
        });
    }
    auto list = ScrollW(makeWidget(column(std::move(rows))), contentHeight);
    list.layout.weight = 1;     // Expanded：吃掉剩余主轴空间

    auto page = column(std::move(panel), std::move(detailButton),
                       std::move(themeButton), std::move(list));
    page.color = theme.windowBackground;
    return makeWidget(std::move(page));
}
```

首页演示的四个模式：

- **布局交给容器**：`column(...)` 是纵向 Flex，每个子节点靠 `layout`
  （`main`/`weight`/`cross`/`align`/`margin*`）声明排布，App 不写 layout
  函数；resize 由 Flex 级联重排。
- **换肤走事件总线**：主题按钮里 `appThemeToggle()` 后
  `esx_event_emit(kEventThemeChanged)`；`HomePage` 构造函数里
  `listen(kEventThemeChanged, ESX_PRI_NORMAL, ...)` 收到就 `setState()`
  重跑 `build()`（重读 token），reconcile 就地更新颜色。
- **模拟异步数据 + 取消语义**：`onDidEnter` 起 `std::thread` 睡 600ms 后经
  `evk::ui::postUi(...)` 回 UI 线程 `setState()`；`onWillLeave` 置取消标志，
  迟到数据被拦截丢弃。这是「后台数据源 → UI 线程」的标准写法示范。
- **导航**：`pushPage(nav(), std::make_unique<DetailPage>(...), true)`，
  pop 后 Component 由框架自动销毁，页面无需清理 records。

### 4.2 详情页 DetailPage

更纯粹的「结构即代码」，实例状态只有一个 `variant_`：

```cpp
auto card = [&](int i) {
    return Box(theme.scrollItems[(variant_ * 3 + i) % 8]).flex(1.0f);
};
auto cards01 = row(card(0).marginMain(0.0f, appCalcWidth(40.0f)), card(1))
                   .mainSize(appCalcHeight(170.0f))
                   .marginCross(appCalcWidth(100.0f))
                   .marginMain(appCalcHeight(40.0f), 0.0f);
```

`row(...)` 内两个 `.flex(1)` 的 Box 演示了 Row 内等宽分栏；`variant` 递增使
连续 push 时每层配色不同，跳转有感知。

### 4.3 布局参数（FlexSpec）

在 Flex 父容器中生效，非 Flex 父容器忽略：

| 字段 | 语义 |
|---|---|
| `main` | 主轴固定 px；<0 由 weight 决定 |
| `weight` | >0 按比例分主轴剩余空间（Expanded） |
| `cross` | 交叉轴固定 px；<0 stretch 占满 |
| `align` | `cross≥0` 时交叉轴对齐（START/CENTER/END） |
| `marginMainBefore/After` | 主轴前后间距 |
| `marginCross` | 交叉轴两侧间距 |

## 5. 声明式层怎么支撑这套写法（core/src/ui/widget.cpp）

- **`pushPage(nav, component, animated)`**：`build()` → `reconcile` 挂载 →
  给页面注册导航钩子（把 Navigation 的 8 态生命周期转发成
  `onWillEnter/DidEnter/WillLeave/DidLeave` 虚函数）→ `esx_navigation_push`。
  pop 时 `componentPopHook` 负责 `delete` Component（视图树由 Navigation 销毁）。
- **`reconcile`**：对齐 Flutter 无 key 子节点语义——同位置同类型（typeid）
  `updateView` 就地更新（滚动 offset 等内部状态保留），不同类型销毁重建，
  多出的新子节点创建、多出的旧子节点销毁。这就是列表数据到达后能
  「自动增删行」的原因。
- **`setState`**：`mutate()` → `build()` → `reconcile` diff → `requestRender`；
  根 widget 类型变化会告警并忽略。
- **回调槽 trampoline**：控件 C ABI 是「函数指针 + user_data」，每个
  Box/Button/Scroll 的回调经静态 trampoline 转发到 `Element` 持有的
  `std::function` 堆槽；`createView` 注册一次，`updateView` 只覆写槽内容
  （user_data 指针不变，控件无需重注册）。
- **视图销毁归属**：Element 只负责释放回调槽，视图树统一由
  Navigation / `teardownAllComponents` 之外的流程销毁（pop 路径不调
  `teardown`）。

## 6. 设计像素换算（app_metrics）

设计稿基准 1080×2339，等比缩放：

```cpp
g_scaleRatio = std::min(width / 1080, height / 2339);
```

布局里所有尺寸写 `appCalcWidth/Height(设计值)`，渲染用真实像素。
页面是「设计稿适配、真实像素渲染」，横竖屏/折叠屏自适应；SurfaceChanged
只更新基准 + 根视图 bounds，内容重排由 Flex 容器自动级联完成。
