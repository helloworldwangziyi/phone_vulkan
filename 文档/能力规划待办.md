# 能力规划待办

对照 Flutter 能力版图盘点出的缺口，按「改造成本 × 收益」排序。
架构评估结论见文末，各项涉及的代码位置以 `core/include/evk/ui/` 下的
头文件为准。

## P0 框架级能力（架构已留位，优先做）

- [ ] **InheritedWidget（树内依赖下发）**
  - ProxyElement 已存在（widget_tree.h），Flutter 中 InheritedWidget
    即为 ProxyWidget 子类，直接沿用该扩展点
  - 实现：ProxyElement 子类暴露数据；子树 `dependOn` 时沿 `parent_`
    链向上查找并登记依赖；数据变更时通知依赖方 setState
  - 同步 setState 语义下传播比 Flutter 简单
  - 主题 / Locale / MediaQuery 的地基
  - 预估：1~2 天

- [ ] **Theme 主题系统**
  - 依赖 InheritedWidget；`Theme::of(context)` 读取 + 暗色模式切换
  - 控件颜色字号逐步从硬编码迁移到主题读取
  - 预估：2~3 天（含存量控件迁移）

- [x] **布局约束协议（constraints 下行、size 上行）** ✅ 已落地
  - 现状：`configureChild` + `handleBoundsChanged` 自顶向下写死尺寸，
    仅够 Flex 使用
  - 改为 Flutter 式双向协议：父传约束（min/max 宽高），子回报尺寸
  - 牵动全部现有控件，控件越多越贵，**越早做越便宜**
  - 解锁：Stack/Positioned、Wrap、内容自适应控件（按钮包文字）
  - 预估：1~2 周（框架级重构）
  - 落地记录：`BoxConstraints` + `View::layout/performLayout/setPosition`
    （render_view.h），`markNeedsLayout` 冒泡 + `flushLayout` 从根重排，
    `handleBoundsChanged` 已删除；Flex/ScrollView/ListView/Navigation/
    Text/SizedBox/Padding 全部迁移到协议，Text 的 setFlexChild 回灌
    hack 移除；裸 Text 在 Column 里即占实测行高（内容自适应已生效）。
    Stack/Positioned、Wrap、按钮包文字控件的协议地基已具备，控件本身待做。

## P1 产品级能力（不做成不了真实 App）

- [ ] **TextField + IME 文本输入**
  - 框架无架构障碍，属体力活
  - 子项：焦点系统（FocusNode/焦点树）；光标与选区渲染；
    输入法 composition（组合态下划线）；剪贴板
  - 光标定位数学可复用 TextLayout 逐字形度量
  - 三端壳各自对接 IME：Android JNI / iOS ObjC++ / HarmonyOS NAPI
  - 预估：2~4 周（三端排期）

- [ ] **多点触控重构**
  - 现状：`pointer_input.cpp` 单 `g_pointer` 全局态，单指假设
  - 改为 per-pointerId 状态表，注意回归 tap/pan/fling 现有行为
  - 解锁：pinch 缩放、rotate、双指滚动
  - 预估：3~5 天

- [ ] **手势丰富度**
  - long press、double tap、多 recognizer 竞争仲裁
    （当前是「最近接收者 + winner 锁定」，无多识别器竞技场）
  - 依赖多点触控重构
  - 预估：1 周

- [ ] **异步图片管线**

  - 预估：1~2 周（可复用 stb_image）

## P2 渲染效果（接受管线从「唯一」变「多条」）

- [ ] **阴影（elevation）**
  - 方案：SDF 圆角矩形阴影，片元着色器算距离场羽化
  - 需给 `UiVertex` 扩属性或新增第二条管线，不动 compositor
  - 预估：3~5 天

- [ ] **圆角 clip**
  - 现状：scissor 只能裁矩形（`Batch::clip` 为单个 Rect）
  - 方案 A：片元 discard（随阴影方案一起做，扩顶点属性）
  - 方案 B：stencil（render pass 改动大，不建议现阶段做）
  - 预估：3~5 天

- [ ] **隐式动画（AnimatedContainer 式）**
  - animation_scheduler 已有；updateRenderObject 对比新旧属性自动起补间
  - 纯封装层工作，无架构改动
  - 预估：2~3 天

- [ ] **转场动画扩展**
  - Navigator 当前只有滑动转场；补 fade / scale / 共享元素（Hero）
  - Hero 需跨 Route 的元素匹配与飞行层，复杂度较高，可分期
  - 预估：1 周（不含 Hero），Hero 另计

## 架构评估备忘

合理的部分（保持）：
- Widget / Element / View 三棵树忠实复刻 Flutter，职责清晰
- 四类 Widget（Stateless/Stateful/RenderObject/Proxy）扩展点完整
- 立即模式 Canvas + (clip, texture) 合批，与 UI 场景匹配
- 单线程模型 + VSync 合帧，简单可靠

会抵抗扩展的两处（做对应能力前先解决）：
1. ~~布局契约是「父写死尺寸」而非约束协议~~ —— 已解决（见 P0 布局项
   落地记录）：BoxConstraints 双向协议 + 脏冒泡重排
2. 渲染是单通道单管线 —— 阴影/圆角 clip 需扩顶点属性加管线，
   模糊需离屏通道

已知欠账：Element 匹配无 key（见 P3）。
