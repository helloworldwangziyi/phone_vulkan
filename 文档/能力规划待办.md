- [x] **多点触控重构** ✅ 已落地
  - 现状：`pointer_input.cpp` 单 `g_pointer` 全局态，单指假设
  - 改为 per-pointerId 状态表，注意回归 tap/pan/fling 现有行为
  - 解锁：pinch 缩放、rotate、双指滚动
  - 预估：3~5 天
  - 落地记录：`g_pointers` 状态表按 pointerId 分指跟踪，每指独立的
    target/panTarget/scaleTarget、触控阈值与速度采样；同视图 pan 排他
    （防双指同滚双倍速）；平台复用 id 时同 id 残留序列先按 Cancel 收尾。
    pinch/rotate 经 ScaleEvent 同步落地（见下「手势丰富度」）。三端壳
    全量转发多指：Android 逐 id 批量上报 MOVE、iOS 槽位表分配稳定
    pointerId、HarmonyOS 直接透传 touchPoints。

- [x] **手势丰富度** ✅ 已落地
  - long press、double tap、多 recognizer 竞争仲裁
    （当前是「最近接收者 + winner 锁定」，无多识别器竞技场）
  - 依赖多点触控重构
  - 预估：1 周
  - 落地记录：View 新增 onDoubleTap/onLongPress/onScale；竞技场规则
    为「同一序列先到先赢，输家收 Cancel」——pan（超阈值）与 scale
    （同视图集齐双指）胜 tap 系；long press（500ms，计时挂在动画调度
    器每帧 tick）触发只废 tap 系，之后仍可认领 pan；double tap 设了
    onDoubleTap 的目标单击挂起 300ms 等待第二击，超时/别处按下即按
    普通单击结算。Widget 侧新增 gestureDetector（对照 Flutter
    GestureDetector）。ScaleEvent 携带焦点（视图局部）、累计/增量
    scale 与 rotation；会话剩余不足两指自动 End/Cancel，剩余指不追溯。

- [ ] **异步图片管线**
  - 网络下载 → 后台线程解码 → `postUi` 回灌 TextureStore
  - 磁盘缓存 + 内存缓存两级；解码绝不能上 UI 线程（单线程模型）

## P5 性能（高频行情场景，仿 Flutter 优化）

接真实行情数据（tick 级推送、上千根 K 线、30~60fps 刷新）前按序投入。
GPU 侧（合批、纹理上传）无结构性问题，瓶颈全部在 UI 线程的 CPU 侧
「每帧全量重建一切」：顶点、文字排版、Widget 树、布局四件事每帧重来。

- [ ] **帧耗时观测（性能 overlay）** —— 最先做，无观测则调优无据
  - 现状：唯一观测口是首帧一次的顶点/批次数日志（compositor.cpp）
  - 对照 Flutter PerformanceOverlay / DevTools Timeline：FPS + 帧耗时
    分段计时（drainUiTasks / rebuild / layout / paint / 顶点上传）
  - 预估：1 天

- [ ] **重建合并（setState 标脏 + 帧头统一 build）** —— 收益最大一项
  - 现状：setState **同步**重建整棵子树（widget_tree.cpp
    `State::setState` 直接调 `element_->rebuild()`），一帧 N 次
    setState = N 次重建；渲染虽被 requestRender 合帧，重建不会
  - 对照 Flutter：setState 仅标脏入队（scheduleBuildFor + dirty
    elements 表），帧头统一 build，一帧多次 setState 只 build 一次
  - 注意回归点：现有调用点依赖「setState 后布局同步完成」的语义，
    改延迟后需排查 build 后立即读尺寸的代码
  - 预估：3~5 天

- [ ] **数据聚合模式（conflation，采样到帧率）**
  - 现状：watchlist_page 一个 tick 一次 postUi + setState；tick 密
    时每帧帧头 drain 出 N 个任务 = N 次同步重建，必掉帧
  - 模式：后台线程持最新快照 + pending 标志，一帧最多投递一次，
    中间 tick 合并丢弃（人眼不可见）；可在框架侧提供
    postUiConflated helper 固化该范式
  - Flutter 接高频 Stream 同样需自行采样，框架不替做
  - 预估：1~2 天（helper + watchlist 改造示范）

- [ ] **RepaintBoundary / 局部重绘** —— 架构级，K 线图的前提
  - 现状：Canvas 立即模式，帧间无缓存无脏矩形（paint_canvas.h 明写），
    任一变化 → 全树重 paint + 全量顶点 memcpy + 命令缓冲整段重录
  - 对照 Flutter RepaintBoundary：子树绘制结果缓存为独立 layer，
    外部重绘时不再执行 paint
  - 落地形态：标记 boundary 的子树顶点按区缓存，仅数据变化时重建
    该区；K 线图表区首选（蜡烛用 drawRect/drawLine 合批，**勿逐根
    drawRoundRect**——SDF 参数不同即拆批，千根 = 千个 draw call）
  - 预估：1~2 周

- [ ] **文字排版缓存**
  - 现状：`layoutRun` 每次全量 UTF-8 解码 + 逐码点查字形 + 堆分配
    （font_engine.cpp）；右对齐数字列 measure+draw 双跑；单行 Text
    布局期也重量。光栅化/atlas 上传已有缓存，无需动
  - 对照 Flutter Paragraph 缓存：按（文本， 字号， 约束宽）键缓存
    排版结果；行情场景静态文案（股票名/列头）必中，数字串 miss 也
    只需一次排版供 measure 与 draw 复用
  - 预估：2~3 天

- [ ] **图表填充路径性能**
  - 现状：`Path::fill` ear clipping 三角化 O(n²)，每帧重算；千点
    分时/面积填充图 ≈ 每帧 10⁶ 次运算，超帧预算
  - 方案：顶点抽稀（min/max 桶化到像素列）或换单调链三角化；
    均线 strokePath 逐段展开（千段 = 6k 顶点/帧）可接受
  - 预估：2~3 天

## 架构评估备忘

合理的部分（保持）：
- Widget / Element / View 三棵树忠实复刻 Flutter，职责清晰
- 四类 Widget（Stateless/Stateful/RenderObject/Proxy）扩展点完整
- 立即模式 Canvas + (clip, texture) 合批，与 UI 场景匹配
- 单线程模型 + VSync 合帧，简单可靠

会抵抗扩展的两处（做对应能力前先解决）：
1. ~~布局契约是「父写死尺寸」而非约束协议~~ —— 已解决（见 P0 布局项
   落地记录）：BoxConstraints 双向协议 + 脏冒泡重排
2. ~~渲染是单通道单管线~~ —— 已解决（见 P2 阴影/圆角 clip、P4 离屏项
   落地记录）：主管线 + SDF 管线 + 离屏模糊通道（场景纹理 + ping-pong
   高斯 + 合成 blit），效果参数走 push constant 按批下发

已知欠账：Element 匹配无 key（见 P3）；setState 同步重建无合帧、
绘制层无缓存无脏矩形（见 P5，高频行情场景的前置项）。
