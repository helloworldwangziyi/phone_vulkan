# estarx_vulkan 源码导读

本文按数据流顺序，带你从 Java 层一直跟到 GPU 绘制。

## 1. Java 层入口：VulkanSurfaceView

文件：`platform/android/java/com/estarx/vulkan/VulkanSurfaceView.java`

它继承 `SurfaceView` 并实现了 `SurfaceHolder.Callback`：

- `surfaceCreated()` → `NativeBridge.nativeInit(holder.getSurface())`
- `surfaceChanged()` → `NativeBridge.nativeResize(width, height)` → `NativeBridge.nativeRender()`
- `surfaceDestroyed()` → `NativeBridge.nativeDestroy()`

**为什么只渲染一帧？**

示例为了最小化，仅在 `surfaceChanged()` 时调用一次 `nativeRender()`。若要做动画，应在 Java 层启动一个 `Choreographer` 或 `Thread`，每帧调用 `nativeRender()`。

## 2. JNI 桥接：bridge.cpp

文件：`platform/android/cpp/bridge.cpp`

它声明并调用两个 C 链接工厂函数：

```cpp
extern "C" evk::IPlatform* evkCreateAndroidPlatform(JNIEnv* env, jobject surface);
extern "C" void evkDestroyAndroidPlatform(evk::IPlatform* platform);
```

这两个函数定义在 `core/src/platform_android.cpp` 中，用 C 链接是为了让 JNI 层不需要知道 C++ 类布局。

`bridge.cpp` 维护全局的 `g_renderer` 与 `g_platform`，生命周期与 Surface 同步。

## 3. Android 平台实现：platform_android.cpp

文件：`core/src/platform_android.cpp`

### createVulkanSurface

```cpp
window_ = ANativeWindow_fromSurface(env_, surface_);

VkAndroidSurfaceCreateInfoKHR createInfo{};
createInfo.sType = VK_STRUCTURE_TYPE_ANDROID_SURFACE_CREATE_INFO_KHR;
createInfo.window = window_;

vkCreateAndroidSurfaceKHR(instance, &createInfo, nullptr, surface);
```

这就是 Android 特有的 Surface 创建方式：`Surface` → `ANativeWindow` → `VkSurfaceKHR`。

### getSurfaceSize

```cpp
*width  = ANativeWindow_getWidth(window_);
*height = ANativeWindow_getHeight(window_);
```

## 4. Vulkan 核心：renderer.cpp

文件：`core/src/renderer.cpp`

### Shader 内嵌

文件开头有两个 `static const uint32_t triangle_XXX_spv[]` 数组，对应 `core/shaders/triangle.vert` 和 `triangle.frag` 的 SPIR-V 字节码。这样不需要在构建时调用 `glslc`。

### createInstance

关键点：

```cpp
std::vector<const char*> extensions = {
    VK_KHR_SURFACE_EXTENSION_NAME,
#ifdef __ANDROID__
    VK_KHR_ANDROID_SURFACE_EXTENSION_NAME,
#endif
};
```

`VK_USE_PLATFORM_ANDROID_KHR` 在 Android 构建时由 `CMakeLists.txt` 定义，这样 NDK 才会暴露 Android Surface 扩展。

### pickPhysicalDevice

必须同时满足：

1. 至少有一个 Queue Family 支持 `VK_QUEUE_GRAPHICS_BIT`。
2. 至少有一个 Queue Family 支持 `vkGetPhysicalDeviceSurfaceSupportKHR` 返回 `VK_TRUE`。
3. 支持 `VK_KHR_swapchain` 扩展。

### createSwapchain

注意 pre-transform：

```cpp
vkGetPhysicalDeviceSurfaceCapabilitiesKHR(physicalDevice_, surface_, &caps);
createInfo.preTransform = caps.currentTransform;
```

在 Android 上这样做可以让 SurfaceFlinger 避免额外的旋转合成，性能更好。

### createGraphicsPipeline

- 使用动态 `VK_DYNAMIC_STATE_VIEWPORT` 和 `VK_DYNAMIC_STATE_SCISSOR`，因此可以在 `recordCommandBuffer()` 中根据当前 Swapchain 尺寸设置。
- Vertex Shader 输入布局：位置（`vec2`，location 0）+ 颜色（`vec3`，location 1）。
- 顶点步长 `sizeof(float) * 5`。

### createVertexBuffer

顶点数据硬编码：

```cpp
const float vertices[] = {
    // positions     // colors
     0.0f, -0.5f,   1.0f, 0.0f, 0.0f,  // 顶部红色
     0.5f,  0.5f,   0.0f, 1.0f, 0.0f,  // 右下绿色
    -0.5f,  0.5f,   0.0f, 0.0f, 1.0f,  // 左下蓝色
};
```

使用 `HOST_VISIBLE | HOST_COHERENT` 内存，直接 `memcpy` 上传。

### render

标准双缓冲同步：

```text
vkAcquireNextImageKHR(imageAvailableSemaphore)
记录 CommandBuffer
vkQueueSubmit(inFlightFence, 等待 imageAvailable，信号 renderFinished)
vkQueuePresentKHR(等待 renderFinished)
```

如果 `vkAcquireNextImageKHR` 返回 `VK_ERROR_OUT_OF_DATE_KHR`，或 `vkQueuePresentKHR` 返回 `OUT_OF_DATE/SUBOPTIMAL`，则调用 `recreateSwapchain()`。

### recordCommandBuffer

每帧动态设置 viewport 和 scissor：

```cpp
vkCmdSetViewport(cmd, 0, 1, &viewport);
vkCmdSetScissor(cmd, 0, 1, &scissor);
```

然后绑定顶点缓冲并绘制 3 个顶点：

```cpp
vkCmdDraw(cmd, 3, 1, 0, 0);
```

背景色在 `clearColor` 中设置：

```cpp
VkClearValue clearColor = {{{0.06f, 0.06f, 0.09f, 1.0f}}};
```

## 5. 修改练习

试着改以下地方，观察运行效果：

- **背景色**：`recordCommandBuffer()` 里的 `clearColor`。
- **顶点位置/颜色**：`createVertexBuffer()` 里的 `vertices` 数组。
- **三角形数量**：把 `vkCmdDraw(cmd, 3, 1, 0, 0)` 改成 `vkCmdDraw(cmd, 6, 1, 0, 0)` 并补充更多顶点，可以画四边形。
