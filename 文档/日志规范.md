# 日志规范

项目运行时日志统一使用以下结构：

```text
[evk][<feature>][<event> key=value ...]
```

例如：

```text
[evk][render][first_frame vertices=1536 batches=24]
[evk][swapchain][configured width=1080 height=2400 transform=0]
[evk][texture][create_failed texture_id=3 action=retry_next_frame]
```

## 字段约定

- `evk`：固定项目标识，不得修改或省略。
- `feature`：稳定的功能域，使用小写 `snake_case`，用于过滤日志。
- `event`：稳定的事件名，使用小写 `snake_case`，必须是第三段第一个 token。
- 数据字段：使用 `key=value`，字段名使用小写 `snake_case`，多个字段以空格分隔。
- 日志级别：由日志 API 表达，不在正文重复写 `info`、`warning` 或 `error`。
- 时间、级别、进程和 tag 由 Logcat、hilog 等系统采集器作为元数据展示，消息正文必须从 `[evk]` 开始。

当前功能域包括：

| 功能域 | 范围 |
|---|---|
| `app` / `lifecycle` | App 启动、挂载与生命周期 |
| `android` / `ios` / `harmony` | 平台壳与 surface |
| `vulkan` / `validation` | Vulkan 上下文与校验层 |
| `renderer` / `render` | 帧编排、提交与帧统计 |
| `swapchain` / `pipeline` / `offscreen` | GPU 渲染设施 |
| `texture` / `text` | 纹理、字体与文本 |
| `ui_tree` / `layout` | UI 树与布局 |
| `navigation` / `watchlist` | 导航与示例业务 |
| `storage` / `accessibility` | 存储与无障碍 |

## C++ 调用格式

C++ 必须通过 `EVK_LOGV/D/I/W/E`，第一个参数传功能域，第二个参数传事件和数据：

```cpp
EVK_LOGI("render", "first_frame vertices={} batches={}", vertices, batches);
EVK_LOGE("renderer", "acquire_image_failed result={}", result);
```

日志封装会统一生成三段式前缀，调用方不要手写 `[evk]`。

## 平台直出格式

不能使用 C++ 封装的 `NSLog`、HarmonyOS `hilog` 等接口，格式串本身必须以
`[evk][feature][event` 开始，并以 `]` 结束。

## 数据规则

- 错误日志应提供失败事件，以及可用的 `reason`、`phase`、`operation` 或 `result`。
- 尺寸、数量、标识等动态值必须带字段名，禁止只输出无语义数字。
- 禁止输出密码、令牌、完整用户隐私、行情账号等敏感数据。
- 高频路径避免逐帧或逐 tick 打日志；需要统计时优先聚合后定期输出。
- 禁止自由叙述式正文，例如 `failed to create image` 或 `screen size: 1080x2400`。
